# SPIBB with Multiple Behavior Policies

Safe Policy Improvement with Baseline Bootstrapping (SPIBB)
learns a new policy from a fixed offline dataset. 

Standard SPIBB assumes one policy generated the dataset and that
this same policy is the baseline. It guarantees with high probability 
that the new policy is not much worse than a baseline policy.
Where the state-action counts are below a threshold N, SPIBB copies the baseline instead
of improving it.

However, datasets are often pooled from several arbitrary behavior policies. 
Different operators, older versions of a system, exploratory runs.

This project studies SPI in that setting.

## Research Question

When an offline dataset is generated by K arbitrary behavior policies, 
which baseline should SPIBB bootstrap on, and what safe-improvement  
guarantee does each choice give?

Sub questions:

1: With a known baseline pi_j, does the SPIBB guarantee still hold when the data comes from a mix of policies?
2: How does the improvement over pi_j depend on the share of the data that pi_j generated?
3: Behavior cloning on pooled data could estimate a mixture pi_mix, whose value is roughly the weighted average of the K policies. How does improving over pi_mix compare with improving over the best behavior policy?

# General approach:

We collect data from several different policies and remember which policy produced each step.
Because the environment behaves the same no matter who is acting, we pool all the data to learn how the environment works.
The policy label is only used to decide what we compare against: either one specific known policy, or an "average" policy estimated
from all the data. The new policy we learn only looks at the current state, because in practice there's no label when you use it.

## Reproducing standard SPIBB

Requires Python 3.10+.

```powershell
git clone --recurse-submodules <our-repo-url>
py -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python src/reproduce_spibb.py --seeds 1 2 3
```

Expected: `baseline 5.22, optimal 11.74`. Values stay at 5.22 up to 200 trajectories, reach about 11.55 at 1,000 and 11.74 from 5,000. Results go to `results/e1_reproduction.csv`.
